# 程序化战术场景升级

这版在现有 Three.js 项目中升级地图、双方人物、第一人称手臂与武器材质，方向是克制的工业军事设施。三角洲行动、CS、使命召唤作为视觉方向参考；当前仍是程序化 WebGPU 资产，不代表达到这些商业游戏的最终美术质量。

## 地图与光照

`src/visual/facility-detail.js` 根据已有掩体类型构建不同的视觉结构：

- 货运集装箱：波纹侧板、角件、门缝、锁杆、搭扣和编号。
- 设备机柜：分仓面板、服务器层架、散热槽、把手和状态灯。
- 冷却机组：双风扇、轮毂、叶片、格栅及侧面百叶。
- 维修台与运输箱：抽屉、台面、金属锁扣、加强筋和嵌入式把手。
- 建筑细节：高窗、门楣管线、起重梁、吊架、混凝土拉结孔、货运地面字样和轮胎痕。

大体积掩体沿 `BOXES` 的实体轮廓布置；新增构件为表面浅浮雕、地面贴花与高处结构。共享碰撞和导航数据没有修改。

`src/world.js` 调整日光方向、环境补光、雾和泛光。中高画质使用 GTAO、FXAA、第一人称自阴影及附近顶灯投影；高画质使用两盏局部投影灯，中画质使用一盏。低画质关闭 GTAO、体积散射、阴影和泛光。标牌合入一张共享图集，静态场景继续按材质合批。

混凝土和地面改用 Poly Haven 的 CC0 三通道 2K 材质，并使用 1K 仓库 HDR 经 PMREM 预过滤生成粗糙反射。扫描包约 15.85 MiB，来源见 [licenses/poly-haven-cc0.md](licenses/poly-haven-cc0.md)。旧版生成的混凝土 / 地面贴图不再重复加载。

天窗现在是屋顶真实开口，玻璃不投射实体阴影，开口扩展到新翼的屋顶。`src/visual/atmosphere.js` 逐步采样场景深度、方向光和最多两盏附近顶灯的阴影，产生受遮挡的单次散射与丁达尔光束；中画质使用 24 步采样，高画质使用 32 步。TSL 后处理使用场景深度，逐帧同步相机与阴影矩阵；阴影目标在创建后处理之前完成分配，避免采样占位纹理后重建附件使已有绑定失效。`src/visual/facility-occlusion.js` 沿共享碰撞轮廓生成静态地面遮蔽图，为远离动态投影灯的掩体与墙根保留接触阴影。方向光和枪械阴影相机在修改范围后显式更新投影矩阵。

## 场景材质与照明补强

通过用户指定的 `C:/project/image` 本地服务顺序生成三张纹理，原始图为 1254×1254，处理后为 1024×1024 WebP。提示词、来源、处理步骤和通道路径保存在 `public/art/manifest.json`：

- `facility-epoxy`：维修区与集结区地坪的磨损树脂涂层。
- `facility-paint`：集装箱、机柜、起重梁、管线与屋面涂层。
- `facility-plaster`：墙裙的旧涂料与细微表面损耗。

每张素材经过亮度和饱和度整理、边缘匹配及 3×3 平铺预览检查；法线为高频亮度近似生成的微表面细节，粗糙度为保守估算，并非实测 PBR。运行时只加载本地资源，不依赖生图服务。既有 2K 扫描混凝土与仓库 HDR 继续使用。

`src/visual/facility-surfaces.js` 在已有材质着色器上叠加世界坐标中的缓慢颜色变化、墙根积灰及局部地坪抛光，保留扫描法线和静态接触遮蔽。涂层的 UV 改按世界尺寸投影，避免把一张纹理任意拉满整个设备。建筑墙体增加小倒角，屋顶增加接缝与通风管道，外墙增加浅薄服务箱、百叶和编号。

顶灯调整至实际灯具的坐标，北货运区偏冷、南维修区偏暖；扩大真实天窗开口，调整日光方向和强度，增强受遮挡的光斑与散射。GTAO 稍微增强，环境补光降低以保留局部明暗。

`src/visual/wet-floor.js` 用一个共享平面反射目标表现货运仓、南北新翼、中央门厅与两侧外环的潮湿区域，反射实际场景中的灯具、设备与人物。程序化遮罩由多尺度噪声、排水带和局部水洼组成，保留干湿交界；湿区同步降低地面粗糙度，视角菲涅耳和缓慢细波纹控制反光。低画质关闭平面反射，中画质反射高度为 512 像素、高画质为 768 像素，宽度按窗口比例缩放，不开启反射目标的多重采样。GTAO 的法线覆盖渲染不会再次触发反射场景。`npm run test:wet-light` 在 GPU 上检查五个区域的湿区覆盖，并通过开关效果的像素差异验证四个视角的反射、散射和局部灯光，同时检查移动后的相机与阴影矩阵同步。截图和报告输出到 `artifacts/wet-*.png` 与 `artifacts/wet-light-report.json`。

这套反射增加一次场景绘制，尚未进行独立显卡/集显的帧率基准。自动检查验证三档画质开关、资源色彩空间、贴图边缘、无外部请求和无浏览器/着色器错误；画面质量仍需结合实机截图判断。

## 参考 demo 的第二轮场景调校

参考 `demo/demo.html` 中的磨损层、室内探针与遮挡距离软阴影，继续补强现有场景：

- 涂层圆角增加稀疏露底，纵向锈迹、近地污渍、粗糙度与金属度分别控制。墙面涂料不套用金属掉漆。
- `src/visual/damp-mask.js` 为地面 PBR 与反射共用潮湿遮罩，湿区同步降低地面颜色亮度与粗糙度，反射使用菲涅耳透明度和波纹扰动。
- `src/visual/facility-probe.js` 在加载后为货运区与维修区各捕获一次 128² 浮点立方体贴图，再通过 PMREM 预过滤。设备使用对应区域的屋顶、灯具与掩体反射。捕获不包含湿地反射与目标特效，不会每帧重复执行；扫描 HDR 继续作为其他材质的环境。为弥补捕获场景缺少多次漫反射，在捕获与设备着色中保留人工补光，属于近似环境照明，并非动态全局光照。探针没有视差校正，区域内各设备共用一个捕获位置。
- `src/visual/sun-shadows.js` 为设施方向光加入遮挡搜索和可变半影。中画质使用 8 次遮挡搜索与 10 次滤波，高画质使用 8 + 16 次；低画质沿用关闭阴影的设置。顶灯和第一人称仍使用各自的原有 PCF，避免将日光的距离参数套到近景灯光上。

新增探针增加加载时的场景捕获与显存占用，可变半影增加场景材质的阴影采样。尚未做真实硬件帧率基准。截图对比见 `artifacts/reference-before-after.jpg`；验收检查探针分配、捕获后灯光状态恢复、画质采样分档及浏览器着色器错误。

## 人物与武器

人物第五版详见 [character-replacement.md](character-replacement.md)。双方装备几何不同，换边时会更换整个角色模板，而不是只换颜色。蒙皮、动画和 IK 继续用于所有队友与敌人。

`src/visual/tactical-gear.js` 提供曲线扫掠几何、程序化金属 / 聚合物 / 织物细节、第一人称袖子及手套。武器增加机械销、选择杆、背带环、部分枪型的导轨灯、压力线及枪口环。七种武器继续沿用原有枪口、瞄准和操作逻辑。

`ModelKit.batchWeapon()` 按材质合并静态零件并缓存几何；活动枪栓和透明镜片不参与合并。在相同双人展示场景中，绘制调用从升级前的 297 次降至 51 次。该数字来自同一套浏览器展示脚本，不是 FPS 测试，也不代表整场对战性能。

## 渲染后端

主场景和装备库均使用 Three.js `WebGPURenderer`，禁用自动 WebGL 回退。原有 GLSL 材质钩子与后处理已迁移到 TSL：颜色 / 粗糙度 / 金属度节点、深度阴影过滤、实例化粒子、枪口火焰、平面反射、深度限定体积散射，以及 GTAO / Bloom / FXAA 节点。场景目标保持单采样以兼容深度读取，最终画面通过 FXAA 抗锯齿。画质切换保留阴影灯和附件，通过强度与更新开关控制投影。设备初始化、设备丢失和 GPU 校验错误均提供错误处理。

WebGPU 需要 HTTPS 或本机 localhost；局域网使用受信任证书或 HTTPS 反向代理，配置见 README。`demo/` 是外部参考文件，不属于项目迁移范围。

## 验证与查看

```sh
npm run build
npm test
npm run test:webgpu
npm run test:wet-light
npm run test:muzzle
npm run test:visual
npm run test:art
npm run test:arsenal
npm run test:browser
```

视觉检查覆盖独立骨骼、双方造型、换边后的模型与姓名、双方 × 七种武器 × 三个俯仰角 × 站立与蹲伏共 84 个握枪姿势、三档画质及其实际开关、绘制批次、资源及浏览器错误。材质检查验证本地扫描法线长度、数据色彩空间、HDR 来源及无外部运行时请求。规则测试覆盖比赛与武器逻辑；浏览器测试覆盖菜单、战斗、结算和双客户端局域网。

运行视觉检查后，在 `artifacts/` 查看：

- `visual-combat.png`：第一人称武器与双方角色。
- `original-soldiers-front.png` / `original-soldiers-back.png`：双方全身。
- `original-soldier-closeup.png` / `original-soldier-crouch.png`：近景与蹲伏。
- `map-north-freight.png` / `map-south-service.png` / `map-staging.png`：地图分区。
- `visual-report.json`：姿态误差、面数、绘制调用和自动化检查结果。

开发运行：`npm run dev`。截图是实际浏览器渲染结果；程序化造型、面部细节、布料变形及光照仍有明显的 程序化原型特征，后续要追求商业级写实效果，需要进一步制作雕刻烘焙资产、更细的角色拓扑与动画，以及逐场景的光照调校。
