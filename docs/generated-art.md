# Zero Facility 生图材质包

本次使用 `C:\project\image` 的本地文字生图服务，制作并接入现代军事工业设施风格的材质。运行游戏不依赖此服务。

## 已接入素材

| 素材 | 用途 | 平铺 |
| --- | --- | --- |
| concrete | 混凝土墙与隔断，约 2 米一个周期 | 是 |
| floor | 耐磨环氧地坪，约 2 米一个周期 | 是 |
| gunmetal | 枪械机匣、导轨、金属边缘与设备外壳 | 是 |
| fabric | 第一人称袖子与已有布料部件 | 是 |
| service-panel | 设备柜和配电箱正面 | 否 |

每类包含颜色、微表面法线、粗糙度三个 1024×1024 WebP 文件，共 15 张，约 **6.01 MiB**。正式文件位于 `public/art/materials/`，提示词、生成时间、实际源图尺寸和处理方式记录在 `public/art/manifest.json`。

基础颜色来自文字生图。辅助法线仅从高频亮度变化估计细微表面起伏，粗糙度采用按材质设定的保守范围；它们不是测量得到或由接口直接生成的校准 PBR 通道。设备面板的凹槽等主要形状仍包含图片中的明暗，不能当作完整三维几何。

## 统一风格

采用冷灰混凝土、蓝灰地坪、暗石墨枪械、低饱和军绿织物，辅以墙面下半部军绿色涂装、少量琥珀警示和青色状态灯。可读的文字标识、电气警告与地面模板漆通过单张程序化图集绘制，避免生图文字错误。

人物仍使用现有的带贴图人类士兵，保留原来的 UV 贴图和骨骼动画；这次没有生成或替换三维人物，也没有把平铺织物直接覆盖整张角色贴图。

## 制作流程

1. 生图服务在 `http://127.0.0.1:3000`，从服务目录运行 `npm start`。配置继续由该项目管理，游戏前端没有任何 API 密钥。
2. 单张生成：`node scripts/generate-art.mjs concrete`。可选名称见表格。每次只提交一张，默认沿用服务模型；已有成功记录会跳过。
3. 原图及元数据保存在忽略提交的 `artifacts/ai-source/`，不会覆盖同一次成功生成的源图。脚本默认从 `C:/project/image/.env` 读取本地鉴权信息，不输出密钥。
4. 后处理：`node scripts/process-art.mjs`，或追加单个素材名称。需要本机 Chrome / Edge 或 `CHROME_PATH`。使用浏览器 Canvas 完成缩放、亮度与饱和度校正、边界羽化与对齐、辅助通道计算和 WebP 压缩。
5. 平铺预览位于 `artifacts/art-previews/`；边界匹配后还要人工检查 3×3 预览，数值相等不能证明重复图案完全不可见。
6. `npm run build` 后运行 `npm run test:art` 与 `npm run test:visual`，检查实际加载、色彩空间、解码后的接缝、人物动画和效果。

本次共有 5 张成功输出。织物首次请求收到 HTTP 504，完成其他素材后间隔补做一次成功；本地服务没有上游任务查询能力，无法判断超时的首次请求是否产生计费，因此脚本没有自动重试策略。

## 游戏中的加载

启动时等待人物和材质完成加载，失败时显示资源加载错误。颜色贴图采用 sRGB，法线和粗糙度采用数据色彩空间，平铺材质启用重复采样与各向异性过滤。多个部件共享同一组贴图，旧的程序化占位贴图完成替换后释放。

发布时一并发布 `dist/art/` 与 `dist/models/`。素材已固化在项目中，生图服务关闭后仍可正常游戏。
